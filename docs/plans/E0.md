## Scope summary

E0 sets up and checks the development environment before any library code exists: the Rust 1.95
pin and `.gitignore`; the standalone probe `tools/env-check/` (device properties, element-wise
add in f32/f64 at vector size 1 and the widest size, u32 atomic histogram, MPI allreduce, JSON
report); the remote-test runner `scripts/hpc/` with one job script per target, `status.sh` and
`cancel.sh`; and a complete `docs/dev-environment.md` for the M3 Max, Myriad V100, Myriad A100
and Locust.

- [x] **T1 env-check: device probe, kernels and report**
  - Goal: env-check opens each compiled-in runtime, records properties, runs and checks the
    kernels, writes the JSON report.
  - Crates/files: `tools/env-check/src/{lib,main,report,probe,kernels}.rs`.
  - Public API added or changed: none (binary outside the workspace). CLI:
    `env-check [--runtime cpu|metal|cuda|all] [--elements N] [--out PATH] [--mpi-only]
    [--expect-sm NN] [--expect-cuda-major M]`; exit 0 iff every check passes.
  - Content (CubeCL 0.11 names):
    - devices `Device::cpu()`, `Device::metal_msl(WgpuDeviceKind::DefaultDevice)`,
      `Device::cuda(i)` for every visible GPU; `Device::client()` → `Client`; no runtime struct.
    - `properties().identity.{name, fingerprint}`; f64/u64 via `supports_type`; u32 atomic add
      via `atomic_type_usage`; `memory.max_page_size`; `hardware.{max_bindings, max_cube_count,
      plane_size_min, plane_size_max, load_width, vector_register_count, max_units_per_cube,
      max_cube_dim}`; `io_optimized_vector_sizes(4)` and `(8)`.
    - element-wise add over 10^7 elements, `#[cube(launch_unchecked)]` generic over `N: Size`
      (bound written literally `Size`), at size 1 and the widest IO-optimized size, cube count
      from `calculate_cube_count_elemwise`, bounds check in the kernel, checked `usize`
      arithmetic, SAFETY comments on `launch_unchecked`/`from_raw_parts`; compared bitwise with
      the host sum.
    - f64: reported `unsupported` on Metal; a failure on CPU and CUDA, where the design says
      it is supported.
    - u32 atomic histogram (`&[Atomic<u32>]`, `fetch_add`) compared with a host histogram.
    - `HostInfo`: OS and version, CPU model, hardware threads, P/E core counts and
      `hw.optional` SIMD flags on macOS, `/proc/cpuinfo` flags on Linux, rustc version.
  - Tests: `cpu_runtime_passes_f32_f64`, `metal_passes_f32_reports_f64_unsupported`,
    `report_is_valid_json`; unit tests for report serialisation and host reference results.
  - Verify: `cargo test --manifest-path tools/env-check/Cargo.toml --features cpu,metal`
  - After: T0
  - Parallel with: T3
  - Risks / notes: the design prescribes `calculate_cube_count_elemwise` here; `LaunchPlan`
    arrives in M2 and env-check is not library code.
