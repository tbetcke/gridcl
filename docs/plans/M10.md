## Scope summary

M10 hardens the host-staged halo exchange (ADR-0059) and adds `local_gpu_index` (ADR-0026, ADR-0060). It collapses `DeviceClass` to `{Cpu, Gpu}` and re-chooses `vector-policy.toml` and `degree-policy.toml` as four generic sets with the candidate protocol and the generic decision rule (ADR-0057, ADR-0058). It records the throughput benchmarks at p = 1, 4 and 8, and reports the p = 8 / p = 4 ratios against ADR-0042's bounds. It ends with examples that run on the CPU runtime and a GPU backend, and with complete rustdoc.

## Findings from planning

Read against main at ae8d644.

1. **Host-staged exchange** (`gridcl-parallel/src/scatterer.rs`):
   - `exchange_blocks` (`:276`) packs, calls `to_host`, then `CommDyn::neighbour_all_to_all_v_bytes`;
   - `forward` allocates a fresh receive buffer and calls `write_host` (`:194`);
   - `reverse` builds `[zeros | received]` on the host and uploads all of it (`:236`);
   - `DeviceBuffer::write_host` copies the data into a fresh padded `Vec` (`gridcl-device/src/buffer.rs:264`), which `Client::write` copies from pageable memory (`cubecl-cuda-0.11.0/src/compute/driver.rs:146`);
   - `Client::staging` (`cubecl-runtime-0.11.0/src/client.rs:844`) moves bytes into pinned staging.
2. **Halo measurements (ADR-0059, 2026-11-16).** These are the baseline for the hardening.
   - **Upload slower than download:** host to device (H2D) of 2.4 MB takes 3.2 ms (GH200) and 6.5 ms (A4000), against 0.3–0.4 ms device to host (D2H).
   - **CPU runtime:** `reverse` costs 35–45 ms at every halo size, against 0.1–0.9 ms for `forward`.
   - **Metal:** about 300 µs per step.
   - The probe was a throwaway crate (deleted with the plan commit); T6 rebuilds it as a gridcl-bench binary.
3. **No `local_gpu_index`** and no shared-memory split anywhere. `gridcl_testing::test_client()` always opens device 0 (`gridcl-testing/src/lib.rs:174`).
4. **`DeviceClass` has four variants** (`gridcl-device/src/policy.rs:90`) and classes CPUs by `load_width`.
   - Four-element arrays keyed on it: `policy.rs:299`, `gridcl-geometry/src/strategy.rs:164`, `gridcl-bench/src/record.rs:343`, `decide_degree.rs:71, 507`, `perf_record.rs:28`, `high_order_record.rs:78, 86`.
   - Both TOML files have one table per old class.
   - The 41 committed records store the old class names.
   - Tests that read the live TOML files: the four in `perf_record.rs`, all eight in `high_order_record.rs` (through `policy()` at `:373`), and `policy.rs:555 policy_covers_every_kind_and_class`.
5. **gridcl-bench has no candidate protocol.**
   - `RUNS = 10` (`protocol.rs:27`).
   - `check_protocol` (`high_order_record.rs:264`) accepts 5 runs on CPUs only.
   - `perf_record.rs` asserts 10 runs.
   - Records lack `load_width`.
6. **Pack and PullBack were never measured** (`decide.rs:499`).
7. **`mesh_throughput`** measures entities per second on P1 tetrahedron and hexahedron boxes, and factors per second on P2 tetrahedra only (degree-4 rule, f64). It has no degree option.
8. **No examples**, except `ptscotch-sys/examples/threading_probe.rs`, which is built and never run.
9. **Rustdoc.** No crate sets `missing_docs`. `RUSTDOCFLAGS="-W missing_docs"` reports 223 items at default features:

   | Crate | Items |
   | --- | ---: |
   | gridcl | 12 |
   | gridcl-device | 60 |
   | gridcl-geometry | 6 |
   | gridcl-testing | 11 |
   | gridcl-bench | 134 |

   CI's `cargo doc` runs at default features only.
10. **Factor plans** use `live = 2·tdim·gdim + 2` under every strategy (`gridcl-geometry/src/layout.rs:480–520`). Plans are made in `layout.rs`, `layout_loops.rs`, `pull_back.rs`, `sumfact/`, `basis_eval/`, `shared.rs` and `cooperative/`.
11. **Follow-ups from earlier milestones not in M10** (question 13; carried into the review's follow-ups): L6, thread placement (ADR-0020), a few-bin histogram, the nightly p ≥ 5 job, `Strategy::{ALL, name}` in the hidden listing, the double `per_group` call, C17, C18, C20, and the committed sweeps' check errors (the degree merge leaves out records whose check error is not finite, ADR-0060 item 3).
