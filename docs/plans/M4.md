## Scope summary

M4 adds gridcl's own Gmsh MSH 4.1 reader and writer (ASCII and binary, either byte order, either
`size_t` width), the generated element table of A.7, the serendipity upgrade (8 → 9, 20 → 27,
15 → 18, 13 → 14), MeshTags from physical groups by device key matching against created entities,
elementary tags as secondary tags, D_TOP and D_GEO inference, and origin ids from node and element
tags. It is serial: `gmsh::read` takes any `Comm` but requires one rank until M8. It adds the
`tags: TagRegistry` field of Listing B3 (ADR-0012), and commits a fixture corpus written by a
pinned Gmsh, with mshio as the test oracle.

## Planned public API and rules (ADR-0022)

Following M3's and M3s's precedent, this fixes what ADR-0022 must decide before T0.

- **Crate split (question 2).** gridcl-io cannot see `Mesh`, `MeshBuilder` or `AnyMesh` (gridcl depends on gridcl-io). So:
  - `gridcl_io::gmsh` holds the host side: the file model, parser, writer, element table, and the conversion between a file and a host mesh description (`GmshMesh`). gridcl-io gains direct dependencies on gridcl-dims, gridcl-refcell and gridcl-device (already transitive; no new crate-graph edge) and dev-dependencies `mshio = "=0.4.2"` and `serde_json`.
  - `gridcl::gmsh` holds `read`, `GmshOptions` and `GmshWriter`, which build or download a `Mesh`; the prelude exports the module `gmsh` and `GmshOptions` (Listing B8 compiles as written, minus the M7/M8 options).
- **gridcl-device, `GridError` (question 3).** New variants, with `Display` lines:
  - `UnmatchedTagElement { dim: usize, tag: i64 }` (Gmsh element tag);
  - `Io(String)` (path and `std::io::Error` text; `GridError` is `Clone`);
  - `Parse { format: &'static str, offset: u64, message: String }` (byte offset, ASCII and binary alike; reused by M5's VTU reader);
  - `UnsupportedElementType { format: &'static str, type_id: i32 }`;
  - `UnknownTag { name: String, dim: usize }`.
- **gridcl-io, `gmsh` module:**
  - `MshFile` with `PhysicalName`, `Entities`, `NodeBlock`, `ElementBlock`, `PartitionedEntities`, `Periodic` (`pub` fields, tags `i64`, coordinates `[node][3]` f64); `pub fn parse(bytes: &[u8]) -> Result<MshFile>`, `pub fn read_file(path: &Path) -> Result<MshFile>`, `MshFile::write_to(&self, w: &mut dyn Write, encoding: Encoding) -> Result<()>`, `pub enum Encoding { Ascii, Binary }`. Unknown sections are skipped; parametric node coordinates are read and dropped; `$Periodic` is stored, not applied. Header counts use checked arithmetic and never size an allocation before the data is there.
  - `pub struct ElementType { pub id: i32, pub cell: CellType, pub degree: u32, pub num_nodes: usize, pub serendipity: bool }`, `pub fn element_type(id: i32) -> Result<ElementType>` (A.7; every other id gives `UnsupportedElementType`), `pub fn lagrange_element_type(cell: CellType, degree: u32) -> Result<ElementType>`.
  - `pub struct GmshMesh { tdim, gdim, nodes: Vec<f64> /* [node][gdim] */, node_tags: Vec<i64>, blocks: Vec<GmshCellBlock>, tag_groups: Vec<GmshTagGroup>, names: Vec<PhysicalName> }`; `GmshCellBlock { cell, degree, nodes: Vec<u32> /* A.5 order */, tags: Vec<i64>, elementary: Vec<i32>, physical: Vec<(u32, i32)> }`; `GmshTagGroup { dim, cell, corners: Vec<i64> /* corner node tags in internal vertex order */, tags: Vec<i64>, elementary: Vec<i32>, physical: Vec<(u32, i32)> }`.
  - `pub fn to_gmsh_mesh(file: &MshFile, comm: &dyn CommDyn, gdim: Option<usize>) -> Result<GmshMesh>` and `pub fn from_gmsh_mesh(mesh: &GmshMesh) -> Result<MshFile>`.
- **gridcl-refcell (question 12):** `pub fn serendipity_upgrade(cell: CellType) -> Result<SerendipityUpgrade, RefCellError>`: the weights of the missing complete-P2 nodes over the file's 8, 20, 15 or 13 nodes (Gmsh order), from the serendipity map evaluated there (host, f64). The serendipity bases stay crate-private.
- **gridcl-topology (question 5):** `Topology::match_entities(&self, dim: usize, keys: &SortKeys) -> Result<DeviceBuffer<u32>>`: keys are sorted local vertex indices (1–4 words; the word count selects the entity type), the result is the flat entity index of each key, `u32::MAX` where none matches. Entity keys are rebuilt from `EntityBlock::vertices` by a sort kernel, concatenated before the tag keys, radix-sorted (stable), grouped by `unique_by_key` (its allowed count read), and resolved by one kernel. Kernels plan with `KernelKind::Scalar` (not on the candidate list).
- **gridcl, tags (question 4):**
  - `pub struct MeshTags { pub dim: usize, pub indices: DeviceBuffer<u32>, pub values: DeviceBuffer<i32> }`: sorted by (index, value); an index repeats only with distinct values (an element in several physical groups).
  - `pub enum Codim { Vol, Bnd, BBnd, BBBnd }`, `Codim::dim(self, tdim: usize) -> Option<usize>`.
  - `TagRegistry` (`Default` is empty): `names() -> impl Iterator<Item = (&str, usize, i32)>`, `lookup(dim, name) -> Option<i32>` (Gmsh allows one name in several dimensions), `physical(dim) -> Option<&MeshTags>`, `elementary(dim) -> Option<&MeshTags>`, `group_size(dim, value) -> Option<usize>` (recorded on the host at read time), `group(dim, value) -> Result<MeshTags>` and `named(codim, name) -> Result<MeshTags>` (device selection whose length is the recorded size, so no count read).
  - `Mesh::tags(&self) -> &TagRegistry`; the private `tags` field of Listing B3; `Mesh::try_clone` deep-clones it. Cells (dim = tdim) use flat numbering over cell blocks in block order.
- **gridcl, `gmsh` (questions 6, 7, 11):**
  - `pub fn read<F: Real, C: Comm>(client: &Client, comm: C, path: impl AsRef<Path>, options: GmshOptions) -> Result<AnyMesh<F, C>>`; `comm.size() > 1` gives `NotYetImplemented("parallel Gmsh read (M8)")`.
  - `GmshOptions` (`Default`, private fields): `gdim(self, usize) -> Self`. `partitioner` and `ghosts` are added in M8.
  - `GmshWriter::new(path)`, `.binary(bool)` (default ASCII), `.write(&Mesh<F, TD, GD, C>)`, `.write_any(AnyMeshRef<'_, F, C>)`; one rank only until M8. GLL geometry gives `UnsupportedNodeFamily` until the device conversion lands in M5 (question 10).
- **Reader rules:**
  - Cell blocks in `CellType` order, cells in file order within a block; two degrees of one cell type in D_TOP give `DuplicateCellBlock` (serendipity cells count as degree 2). A file without elements of dimension ≥ 1 gives `Parse` (question 15).
  - Duplicate node tags and duplicate element tags give `DuplicateOriginId`, checked over the whole file before building. Tags ≤ 0 give `Parse` (Gmsh requires tags ≥ 1; question 19).
  - Tag keys: corner node tags → local vertex indices on the host (a node that is not a vertex gives `UnmatchedTagElement`), then `match_entities`. The result is copied to the host to name the first unmatched element, under CLAUDE.md's I/O exemption (question 20). Physical groups of D_TOP elements tag cells directly.
  - D_GEO as in the design: over all nodes of the file, absolute |z| and |y| against 10^−12 L (a plane at z = c ≠ 0 is therefore 3D); `GmshOptions::gdim` must be 1–3 and not below D_TOP, and fixing it below the inferred D_GEO gives `DimensionMismatch` (question 7).
  - Serendipity: an added face-centre node is shared per face (keyed by the face's sorted corner tags), reuses the node of a complete-P2 neighbour where one exists, and otherwise takes a fresh tag above the file's largest node tag, in order of first use (question 12).
  - f32 meshes: `gmsh::read` emits one `log::warn!` per file on narrowing; `log` is a dependency of gridcl (question 14).
  - Partitioned files read serially ignore the partition; elementary tags come from the parent entities in `$PartitionedEntities` (question 16).
- **Writer rules (questions 8, 9, 11, 19):**
  - Node tags: vertex origin ids; the other nodes are numbered after the largest vertex id. Element tags: cell origin ids; tag elements are numbered after the largest cell id. If any origin id is < 1, all node tags (or all element tags) are shifted by the same constant so the smallest is 1.
  - Tag elements are linear, from `EntityBlock::vertices` (canonical A.6 orientation, so the file's original boundary orientation is not kept).
  - One node block, in the first D_TOP entity. `$Entities` is rebuilt from elementary tags, one entity per (elementary tag, physical-tag set), with bounding boxes from its nodes, point coordinates for dimension 0, and empty boundary lists; untagged meshes get one entity with tag 1. Always three coordinates. Binary is always little-endian with an 8-byte `size_t`.

No M4 kernel is on the candidate list of "Vectorization and CPU execution": the new kernels
(entity-key sort and match resolution in T9, tag selection in T10) plan with `KernelKind::Scalar`,
so there are no vector-size invariance rows. The local job's `GRIDCL_VECTOR_SIZE=scalar` and
`widest` runs still cover the suite. Locust CUDA runs follow T9, T10, T11 and T13, and the
milestone review (ADR-0014). No Kathleen or Myriad run is required: no benchmarks, no multi-GPU
tests, no MPI beyond 4 ranks, and M4 adds no MPI test.
