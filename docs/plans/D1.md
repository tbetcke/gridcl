## Scope summary

D1 gives tetraloma user documentation (ADR-0067): an mdBook in `docs/user/`, published with the API docs
of the nine published library crates at https://tetracl.github.io/tetraloma/, and those crates' API docs
rewritten for users, with a book link on every item and a running example on every function. No public
item, signature or behaviour changes; the developer documents stay where they are.

## Book outline (fixed by T0)

T0 fixes the files and their top-level section headings; the API docs link to these. Tasks may add
headings below them, and do not rename them.

`docs/user/src/`:

1. `introduction.md` — what tetraloma is; features; status; how the documentation is organised.
2. `getting-started/` — `installation.md` (toolchain, Cargo dependencies, runtime features of cubecl);
   `first-program.md` (a mesh, its geometry and a VTU file on the CPU runtime).
3. `concepts/` — `meshes.md` (cells, entities, connectivity, blocks, ownership, ghosts, origin ids);
   `reference-cells.md` (reference cells and the reference-to-physical map); `geometry.md` (Lagrange
   coordinate elements, high-order geometry, GLL and equispaced nodes); `geometric-factors.md` (Jacobian,
   determinant, pseudo-inverse, measure, normals, facet normals); `orientation.md` (manifold orientation,
   permutation bits); `quadrature.md` (rules, facet rules, tabulation); `pull-back.md`;
   `typed-dimensions.md` (`Mesh<F, TD, GD, C>`, codimension, methods that exist only where they make sense,
   `AnyMesh`); `precision.md` (f32 and f64, tolerances, determinism).
4. `elements/` — `reference-cells.md` (vertices, edges and faces of each cell, with figures);
   `lagrange.md` (node counts and orderings, with figures); `orientation-bits.md`; `file-formats.md`
   (Gmsh and VTK cell types and node maps); `basix-dolfinx.md` (conversion).
5. `tutorials/` — `build-mesh.md`; `read-write.md` (Gmsh in; Gmsh, VTU, PVTU and VTKHDF out);
   `iterate.md` (blocks, cells, entities, connectivity, reading data back to the host);
   `geometric-data.md` (points, Jacobians, determinants, pseudo-inverses, normals, measures);
   `quadrature.md` (rules; high-order geometry up to p = 8); `pull-back.md`;
   `tags-submeshes.md` (physical groups, regions, boundary and surface meshes, orientation);
   `distributed.md` (`build_on`, partitioners, ghost modes, cell ordering);
   `halo-exchange.md` (`IndexMap`, `Scatterer`, forward and reverse);
   `parallel-io.md` (parallel Gmsh reading; PVTU and VTKHDF output);
   `kernels.md` (downstream CubeCL kernels over `DeviceGrid`, `GeometryBlock` and `BlockFields`; generic
   algorithms; `with_mesh!`).
6. `devices.md` — the CPU runtime, Metal, CUDA (toolkit and driver), Vulkan, HIP and wgpu; choosing a
   device at run time; f64 support; one GPU per MPI rank (`local_gpu_index`); host–device transfers; the
   performance settings users may change.
7. `features.md` — Cargo features and the system libraries they need (MPI flavours, HDF5, METIS, Scotch,
   PT-Scotch, ParMETIS; `metis` and `parmetis` exclusive; `gpu-aware-cuda` reserved).
8. `troubleshooting.md`, `glossary.md`.

## Programs in tetraloma-examples

Existing ones are kept, and adjusted where a chapter includes them: `read_gmsh`, `surface_submesh`,
`geometric_factors`, `vtk_output`, `halo_exchange` (mpi). New ones:

- `first_program`, `build_mesh`, `iterate_cells`, `pull_back`;
- `distributed_mesh` (mpi), and `parallel_io` (mpi; its VTKHDF part needs `hdf5`);
- `custom_kernel`;
- `devices`, which opens the device that the runtime features and `TETRALOMA_TEST_DEVICE` select and
  prints what the book's device chapter describes.

The figure generator is the module `tetraloma-examples/src/figures.rs`, with `svg_files()`, and the
binary `src/bin/figures.rs`, which writes them to `docs/user/src/figures/`.

## Subagents

At most five at a time (maintainer, 2026-11-20). There are three waves:

- **W1:** T3–T7, the book chapters.
- **W2:** T8–T12, the kernels tutorial and the API docs of tetraloma and tetraloma-geometry.
- **W3:** T13–T15, the remaining API docs and the final book pass.

Each subagent gets:

- the task text;
- the design sections it depends on;
- ADR-0067;
- the book outline;
- the style rules below;
- the rule "If the design is ambiguous or an API must change, stop and return an ADR draft instead of
  deviating."

Subagents edit only their task's files. They run no cargo command (local cargo runs are serialised). They
may run only:

- `mdbook build docs/user`;
- `scripts/check-user-docs.sh --no-build --audit-only <crate>`, which reads the HTML the main session
  built last.

The main session runs each task's cargo verification, one run at a time; `scripts/check-user-docs.sh` takes
a lock for its cargo steps. It sends failures back to the subagent and commits each task separately in
task order.

**Style:**

- British English; second person, present tense; one idea per sentence.
- Maths: KaTeX in the book; Unicode with the book's symbols in rustdoc.
- Every Rust block in the book obtains its device through `cubecl::Device`.
- API doctests may keep tetraloma-testing on hidden `# ` lines, with a visible comment that names what the
  hidden line makes (`// mesh: the unit square in 2 × 1 quadrilaterals`) and links to the tutorial that
  shows how to build it.
- No doctest defines a function without calling it.
