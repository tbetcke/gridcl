## Scope summary

M7 adds vertex weights from a cost model by cell type and degree to M6's distributed dual graph, and the external partitioners behind features: ptscotch-sys and the PT-Scotch wrapper (production default), parmetis-sys and the ParMETIS wrapper, METIS on rank 0 (vendored) and Scotch on rank 0. The acceptance tests partition a 10^6-cell tetrahedral box and a 2 · 10^5-cell hexahedron/prism/pyramid mesh at 4 and 8 ranks (8 on one Kathleen node) and check weighted imbalance, edge cut against sequential Scotch, and seed reproducibility. M7 adds no kernel.

## Findings from planning

1. **gridcl-partition** (`src/{graph,block}.rs`) matches Listing S3 exactly. `Block` ignores `vwgt`. Its graph validation `check` (`block.rs:67-117`) is private and checks lengths and monotonicity only, not `adjncy` ranges, self-loops, symmetry or weight signs.
2. **Stage 2** (`gridcl/src/pipeline/dual_graph.rs:21-76`) builds the facet graph with `vwgt: None`; rows are sorted and deduplicated, so the graph is deterministic. The cell type and degree of every vertex are at hand (`cells.block[i]` → `BlockSpec { cell, degree, family }`; `BlockSpec::num_nodes` = `gridcl_refcell::num_lagrange_nodes`). Stage 3 (`:85-109`) checks length and range and agrees errors; on one rank stages 2–4 are skipped (`builder.rs:381-387`).
3. **Features and sys crates.** gridcl's features `ptscotch`, `parmetis`, `metis`, `scotch` forward to gridcl-partition. `metis` and `scotch` are empty; `ptscotch`/`parmetis` enable empty sys crates and do **not** enable `gridcl-parallel/mpi`, so `CommDyn::raw` is invisible in gridcl-partition. The sys crates are workspace members, so an unconditional `mpi` dependency or bindgen step would break `cargo test --workspace` and `scripts/check-workspace-deps.sh` (dependency rule 5; M0 question 4, "ADR candidate due before M7").
4. **FFI rule.** Listing H1 and CLAUDE.md allow FFI calls only in gridcl-parallel (MPI) and gridcl-device, but the crate table puts the PT-Scotch and ParMETIS wrappers in gridcl-partition (question 1).
5. **Threading.** "Streams and threading" initialises MPI with `Threading::Single`. A PT-Scotch built with `SCOTCH_PTHREAD_MPI` requires `MPI_THREAD_MULTIPLE`. Homebrew's `libptscotch.7.0.14.dylib` contains no such check string (probe in T5; question 13).
6. **No gather/scatter collective** exists in gridcl-parallel. `all_to_all_v` with counts only to rank 0 does it (as `gridcl_testing::parallel::gather_to_root`).
7. **No hexahedron/prism/pyramid mesh.** `mixed_box` is tetrahedron/pyramid/hexahedron. `cube_box(Tetrahedron, 56, 1)` has 1 053 696 cells (n = 55: 998 250).
8. **No partition-quality tooling** (edge cut, weighted imbalance).
9. **Test communicators.** gridcl's `ptscotch`/`parmetis` imply `mpi`; then `ThreadComm` needs `gridcl-testing/mpi` for `CommDyn::raw` (M6 Deviations log, T0), so every such test command adds that feature.
10. **External libraries.**
    - M3 Max: Homebrew Scotch 7.0.14 with PT-Scotch (`SCOTCH_Num` = 32-bit `int`, built against Homebrew Open MPI 5.0.10) and METIS 5.1.0 (`IDXTYPEWIDTH 32`); no ParMETIS (not in Homebrew).
    - Kathleen (checked 2026-10-30, `module --show_hidden avail`): no Scotch, METIS or ParMETIS module and nothing in `/usr/include`; cmake 3.30.5 and the llvm 17 module (libclang) exist. remote-test reads fixed keys only, so library paths go as exports into `KATHLEEN_MODULES`.
    - Crates (not in the local registry; APIs checked in T3 and T4): `scotch` 0.2.1 (`MIT OR Apache-2.0`) links a system libscotch, has no `vendored` feature, no seed API and no `Graph::part`, and hard-codes `/usr/include/scotch` in CPATH; `metis` 0.2.x (features `vendored` default, `use-system`). mpi-sys 0.2.4 already runs bindgen 0.72.1, so libclang is present wherever MPI builds.
    - Hosted CI: the `ptscotch` workflow is a skeleton (installs only `libptscotch-dev`); `libparmetis-dev` is in Ubuntu multiverse (to confirm on `ubuntu-24.04` in T8).
11. **`GmshOptions::partitioner`** and the default-choice rule ("for distributed reads") belong to M8 (ADR-0022 l.134). `MeshBuilder` keeps `Block` (ADR-0026).

## Planned public API and rules (ADR-0029 candidate)

```rust
// gridcl-partition (each type behind its feature; re-exported by gridcl's root and prelude)
#[cfg(feature = "ptscotch")] #[derive(Clone, Copy, Debug, Default)] pub struct PtScotch { /* seed */ }
#[cfg(feature = "parmetis")] #[derive(Clone, Copy, Debug, Default)] pub struct ParMetis { /* seed */ }
#[cfg(feature = "metis")]    #[derive(Clone, Copy, Debug, Default)] pub struct Metis    { /* seed; rank 0 */ }
#[cfg(feature = "scotch")]   #[derive(Clone, Copy, Debug, Default)] pub struct Scotch   { /* seed; rank 0 */ }
impl PtScotch { pub fn seed(self, seed: u32) -> Self; }      // same for ParMetis, Metis, Scotch; default 0
impl Partitioner for PtScotch { /* name() = "ptscotch" */ }  // "parmetis", "metis", "scotch"

// gridcl-device
pub enum GridError { …, PartitionerFailed { name: &'static str, code: i32 }, NeedsMpiCommunicator(&'static str) }

// ptscotch-sys / parmetis-sys (feature `mpi`, off by default)
pub const SCOTCH_NUM_BITS: u32;                     // from the bound SCOTCH_Num
pub const IDX_BITS: u32; pub const REAL_BITS: u32;  // parmetis-sys: idx_t, real_t

// gridcl (hidden test accessor, like ADR-0028 item 3)
impl<F, TD, GD> MeshBuilder<F, TD, GD> {
    #[doc(hidden)] pub fn dual_graph_on<C: Comm>(self, comm: C) -> Result<DistGraph>; // stages 1–2, collective
}
```

**Rules.**

- **Cost model (stage 2):** `vwgt` always `Some`, the Lagrange node count of the cell's (type, degree) (question 2).
- **Graph validation** (every external partitioner, before any FFI call; agreed): Block's length and monotonicity checks, plus `adjncy` in `[0, N)`, no self-loops, symmetry (collective: each edge's reverse is confirmed by the owner of its far end), `vwgt ≥ 0`; and the global totals — `N`, the edge count and the sum of `vwgt` — fit the library's index type (`TooLarge`).
- **Rank-0 partitioners** (`Metis`, `Scotch`): gather degrees, `adjncy` and `vwgt` to rank 0 by `all_to_all_v`, narrow with checks, partition, return the destinations by `all_to_all_v`.
- **Distributed partitioners** (`PtScotch`, `ParMetis`) use `comm.raw()`; with `None` on more than one rank they return `NeedsMpiCommunicator(name)`. A library status other than success returns `PartitionerFailed { name, code }`.
- **Every external partitioner:** `nparts == 1` returns zeros without a library call; balance target 3% (METIS `ufactor` 30, Scotch and PT-Scotch `SCOTCH_STRATQUALITY` with 0.03, ParMETIS `ubvec` 1.03); no edge weights; errors agreed (`RemoteFailure` on the other ranks).
- **Seeds:** PT-Scotch `SCOTCH_randomSeed(seed)` then `SCOTCH_randomReset()` before each call (design). Scotch on rank 0 the same, and METIS too if GKlib's random state is global (checked in T3), under one process-wide mutex. ParMETIS `options = [1, 0, seed]`.
- **Sys crates:** one feature `mpi` each, off by default, enabling the `mpi`, `bindgen` and `build-probe-mpi` dependencies, the bindgen step and linking; without it the crate is empty. gridcl-partition's `ptscotch`/`parmetis` enable `<sys>/mpi` and `gridcl-parallel/mpi`; gridcl's imply `mpi`. Libraries are found through `SCOTCH_DIR`, `PARMETIS_DIR`, `METIS_DIR` (`include/`, `lib/`), else system paths. MPI types are blocklisted in bindgen and taken from `mpi::ffi`. PT-Scotch links `ptscotch`, `scotch`, `ptscotcherr`.
