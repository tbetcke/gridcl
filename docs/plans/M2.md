## Scope summary

M2 builds the device layer of gridcl-device: `Real`, the `DeviceBuffer` family with limit checks
and `VECTOR_PAD` padding, and `check_precision`. It adds `LaunchPlan` and `VectorPolicy`, at
vector size 1 and tile width 16 until M3s, with the `GRIDCL_VECTOR_SIZE` and `GRIDCL_QUAD_TILE`
overrides. It adds the primitives: scan, radix sort, unique-by-key, run-length, histogram,
gather/scatter, segmented reduce, fill and copy. Fill, copy, reduce, the tile-local scan phase,
SortDigits and Gather are generic over the vector size. In gridcl-parallel, M2 builds `CommDyn`,
`Comm`, `CommExt`, `Serial` and an `IndexMap` without ghosts.

## Planned public API and rules (ADR-0007)

This section lists only what the design leaves open. ADR-0007 fixes it, and T0's stubs follow
the accepted ADR. Listing S1, Listing S2 and Listing B3 apply unchanged otherwise.

### gridcl-device: errors and scalars

- `#[non_exhaustive] pub enum GridError` lives in gridcl-device. gridcl-parallel and gridcl re-export it, as they do `Result<T, E = GridError>`.
- M2 variants:
  - `TooLarge`;
  - `AllocationTooLarge { bytes: usize, max: u64 }`;
  - `UnsupportedPrecision { scalar: &'static str, device: &'static str }`;
  - `LengthMismatch { expected: usize, found: usize }`;
  - `Server(ServerError)`.
- `GridError` implements `Display`, `Error` and `From<ServerError>`. Later milestones add variants.
- `ReduceOp { Sum, Min, Max }` moves into gridcl-device. gridcl-parallel re-exports it, so the S2 path `gridcl_parallel::ReduceOp` stays valid.
- `DeviceScalar` is a sealed trait, `CubeElement + Numeric`, for f32, f64, i32 and u32. The typed primitives use it.

### gridcl-device: the `primitives` module

The module is re-exported at the crate root.

- **fill:** `fill<T: DeviceScalar>(x: &mut DeviceBuffer<T>, v: T) -> Result<()>`.
- **copy:** `copy<T: CubeElement>(src: &DeviceBuffer<T>, dst: &mut DeviceBuffer<T>) -> Result<()>`.
  - It copies u32 words, so `size_of::<T>()` must be a multiple of 4.
  - Mismatched lengths return `LengthMismatch`.
- **reduce:** `reduce<T: DeviceScalar>(x, op: ReduceOp) -> Result<DeviceBuffer<T>>` returns length 1. An empty input gives the identity of `op`.
- **segmented_reduce:** `segmented_reduce<T: DeviceScalar>(values, offsets: &DeviceBuffer<u32>, op) -> Result<DeviceBuffer<T>>`.
  - `offsets` are CSR offsets, and the result has one value per segment, reduced in index order.
  - Offsets are clamped to `[0, values.len()]`, and a decreasing offset gives an empty segment.
- **scans:** `inclusive_scan<T: DeviceScalar>(x) -> Result<DeviceBuffer<T>>` and `exclusive_scan<T: DeviceScalar>(x) -> Result<DeviceBuffer<T>>`.
  - Both compute sums.
  - The exclusive scan has length n + 1, and its last element is the total. This is not the usual convention, so the rustdoc of `exclusive_scan` states it first and shows it in its example.
- **gather:** `gather<T: DeviceScalar>(src, idx: &DeviceBuffer<u32>) -> Result<DeviceBuffer<T>>`.
  - An index ≥ `src.len()` yields 0 through an arithmetic mask; the read address is clamped and never out of bounds.
  - An empty `src` gives all zeros and no read.
  - Debug builds read back `reduce(idx, Max)` and panic on an out-of-range index.
- **scatter:** `scatter<T: DeviceScalar>(src, idx, dst: &mut DeviceBuffer<T>) -> Result<()>`.
  - Writes with an out-of-range index are dropped.
  - Duplicate indices are memory-safe, but the result is unspecified and not deterministic. Distinct indices are a documented precondition.
  - Debug builds check it: `histogram(idx, dst.len())` and one `reduce(…, Max)` are read back, and a count above 1 panics.
- **histogram:** `histogram(values: &DeviceBuffer<u32>, num_bins: u32) -> Result<DeviceBuffer<u32>>`. Values ≥ `num_bins` are not counted.
- **SortKeys:** keys of one to four u32 words in a planar, word-major layout.
  - Word w of key i is at `w * pad_len(len) + i`.
  - Word 0 is the most significant.
  - Methods: `uninit`, `from_host` (key-major host data), `to_host`, `len`, `num_words`, `words`, `words_mut`.
- **radix_sort:** `radix_sort(keys: &SortKeys, payload: &DeviceBuffer<u32>) -> Result<(SortKeys, DeviceBuffer<u32>)>`.
  - A stable LSD sort with 8-bit digits.
  - A length of 2^32 or more returns `TooLarge`.
- **run_length:** `run_length(keys: &SortKeys) -> Result<Runs>`, where `Runs { keys, offsets }` and `offsets` has length runs + 1.
- **unique_by_key:** `unique_by_key(sorted: &SortKeys, payload) -> Result<Unique>`, where `Unique { keys, first, group }`.
  - `first` is the payload of each group's first key.
  - `group` gives the group of each input position.

### gridcl-device: rules for every primitive

- **Data-dependent sizes.** Unique and run-length read their count back with one blocking 4-byte read and return exactly sized buffers. ADR-0007 records this as an explicit read under CLAUDE.md's host-copy rule (question 4).
- **One partition per primitive.** A multi-phase primitive computes one `LaunchPlan`: for the `KernelKind` of its vectorized phase, or for the first phase if no phase is vectorized. Every kernel of that primitive derives its scalar ranges from that plan: a unit owns `items_per_unit · vector_size` consecutive scalars, and a cube owns `cube_dim` times that. Scalar phases launch with the same cube count and cube dimension (question 11).
  - Recursive levels (for example the partials of reduce and the tile sums of scan) use a fresh `elementwise` plan per level, until one cube remains.
  - No launch shape comes from anywhere else.
- **Cross-lane operations.** The fixed-order in-vector prefix of ScanTile (lane extracts, comptime unrolled) is an allowed cross-lane operation, like a fixed-order reduction (question 12).
- **Empty inputs.** An empty input never launches. An empty `DeviceBuffer` still allocates one `VECTOR_PAD` block, so no handle has zero size (wgpu rejects zero-size bindings); `len()` stays 0 (question 13).

### gridcl-device: `DeviceClass` and test hooks

- `DeviceClass::for_client(&Client)` detects the CPU runtime by `hardware.num_cpu_cores.is_some()`. It is CpuSimd128, CpuSimd256 or CpuSimd512 from `load_width`; every other device is Gpu.
- The `testing` module exists only with gridcl-device's Cargo feature `testing` (off by default, not stable API); gridcl-testing enables it. It holds scoped, thread-local overrides:
  - `with_properties(DeviceProperties, f)` sets every limit and property gridcl reads;
  - `with_vector_size(VectorSizeOverride, f)` and `with_quad_tile(usize, f)`;
  - `record_plans(f) -> (R, Vec<(KernelKind, LaunchPlan)>)` records the plans made in its scope.
- `VectorSizeOverride { Scalar, Policy, Widest, Fixed(usize) }` is also what `GRIDCL_VECTOR_SIZE` parses into. Precedence: the scoped override, then the environment, then the policy (question 5).
  - `Widest` is the first entry of `io_optimized_vector_sizes(elem_bytes)`.
  - `Fixed(n)` and `Widest` bypass the register budget, but are still clamped by `max_vector` (the data layout).
  - `Policy` applies the register budget.

### gridcl-parallel

- `IndexMap::new(comm: &dyn CommDyn, num_owned: usize) -> Result<IndexMap>`.
  - The owned range comes from `exscan_sum` and the global size from `sum`.
  - Accessors as Listing S2, plus `owned_range()`, `ghosts()` and `ghost_owners()`.
  - M6 adds `scatterer` and the device field.
- `pub struct Neighbourhood` is opaque, with `sources()` and `destinations()`. M2 has only `Neighbourhood::empty()`; M6 builds the graph communicator.

### Dependencies and clarifications

- **Dependencies:**
  - gridcl-testing depends on gridcl-device with the feature `testing`, and gridcl-bench depends on gridcl-device.
  - New workspace dependencies: `proptest` (dev), `bytemuck` (gridcl-parallel) and `toml` (gridcl-device).
  - All three crates are already in the local registry; `bytemuck` and `toml` are already in `Cargo.lock`.
- **Clarifications to the design text:**
  - In CubeCL 0.11, the length given to `BufferArg::from_raw_parts` does not bound the kernel's slice: the handle size does. Every kernel therefore takes explicit lengths, as `num_vectors` in Listing B5 does (question 6).
  - The design has two listings named "Listing S2". ADR-0007 renames the communicator listing S2c.

- [ ] **T7 Radix sort**
  - Goal: a stable LSD radix sort over `SortKeys` with a u32 payload.
  - Crates/files: `gridcl-device/src/primitives/{sort_keys,radix_sort}.rs`.
  - Public API added or changed: `SortKeys`, `radix_sort`.
  - Content:
    - **Partition.** One partition from the SortDigits plan (question 11).
    - **Passes.** One per 8-bit digit, from the last word's lowest digit to word 0's highest. Each pass:
      1. **SortDigits**, vector-generic over keys, reading the planar words: per-cube digit counts in shared memory, written digit-major to `counts[digit · cubes + cube]`.
      2. An exclusive scan of the counts (T5).
      3. A stable scatter that ranks keys within each cube in input order. The scheme is chosen at comptime from the plan:
         - `items_per_unit` > 1 (CPU): per-unit counters in shared memory. They are processed in digit chunks sized from `max_shared_memory_size`, because Grace has 72 units × 256 × 4 B = 72 KiB but only 64 KiB of L1.
         - `items_per_unit` = 1 (GPU): 1-bit split scans in shared memory, over 8 iterations.
    - At most six buffers per kernel.
  - Tests:
    - `primitives_prop::prop_radix_sort` (one to four words, with duplicates, stability checked through the payload);
    - `primitives_large::sort_large` (10^6 and 10^7, two words);
    - `determinism::sort_twice`;
    - `vector_invariance::sort_digits_sizes`.
  - Verify: the kernel-task check set.
  - After: T5, T6

    - If neither ranking scheme fits an `elementwise` plan, stop and draft an ADR (question 10).
