## Scope summary

M3 builds a serial `Mesh` from host arrays with origin ids. It creates edges and faces on the
device by sort-based entity creation, builds connectivity and computes permutation info. On the
geometry side it adds geometry blocks, `QuadRule` and `FacetQuadRule`, the cached E-vectors of the
geometry nodes, the tiled `QuadField`, `measure`, and the factor kernels (X, J, det J, K, facet
normals), which are generic over the vector size. gridcl-testing gains the mesh generators. The
real `Mesh` replaces the M1a stub in the compile-fail tests, and `AnyMesh` and `DeviceGrid`
arrive as change-log row BLK-3 requires.

## Planned public API and rules (ADR-0012, question 2)

This section covers only what the design leaves open or gets wrong. The listings apply unchanged
otherwise, and T0's stubs follow the accepted ADR.

### Crate placement (question 3)

- **gridcl-topology:** `CellBlock<TD>` (Listing B3), `EntityBlock` and `Connectivity` (Listing T1), and the `Topology<TD>` container.
- **gridcl-device:** `ConnKey`, re-exported by gridcl-topology and gridcl (question 7).
- **gridcl-geometry:**
  - `CoordinateElement<TD>` and `GeometryBlock<TD>` (Listing B3), and the `Geometry<F, TD, GD>` container;
  - everything in Listings B4b and B5;
  - **`DeviceGrid`** (Listing B7). `QuadRule::for_grid` and `jacobians_block` live in gridcl-geometry and are generic over it, so it cannot live in gridcl, which depends on gridcl-geometry.
- **gridcl:** `Mesh` and its aliases, `MeshBuilder`, `AnyMesh`, `AnyMeshRef`, `with_mesh!`, `EntityMap` and the prelude. It re-exports everything above.

### gridcl-device additions

- **New `GridError` variants.** gridcl-device depends on neither gridcl-dims nor gridcl-refcell, so cell and family names are `&'static str`, as in `UnsupportedPrecision`.
  - `UnsupportedNodeFamily { cell, family }` and `UnsupportedDegree { cell, degree: u32 }`. gridcl-geometry maps `RefCellError` onto them (M1b question 3).
  - `WrongCellDim { found, expected_tdim: usize }` (M1a follow-up).
  - `DimensionMismatch { expected: (usize, usize), found: (usize, usize) }` (Listing B6).
  - `EntitiesNotCreated(usize)`, `ConnectivityNotCreated(ConnKey)` and `UnsupportedConnectivity(ConnKey)`.
  - `DuplicateOriginId(i64)` and `IndexOutOfRange { index: usize, len: usize }`.
  - `NodeRoleMismatch(usize)`: a node used as a vertex in one cell and as a non-vertex node in another.
  - `DuplicateCellBlock(&'static str)` and `CellNotInRule(&'static str)`.
  - `NotYetImplemented(&'static str)`, for `boundary()` until M9 (question 5).
- **Made public.** gridcl-topology and gridcl-geometry kernels need these, and they must see the `testing` overrides (`testing::properties` is crate-private):
  - `pad_len`, the `SortKeys` plane stride;
  - `device_properties(&Client) -> Arc<DeviceProperties>`, which honours `with_properties` (chunk sizing reads `max_page_size` through it);
  - `debug_assert_bindings`.

### gridcl-refcell additions (host, f64; deferred from M1b, question 8 there)

- `reference_facet_normals(cell) -> Vec<f64>`: the outward unit normal of every facet, in facet order, `tdim` entries per facet.
- `facet_points_to_cell(cell, facet, points) -> Vec<f64>`: maps points from the reference facet into cell coordinates through the facet's vertex list, with A.5's affine rule.
- `canonical_order(entity: CellType, ids: &[i64]) -> Vec<usize>`: the A.6 storage slots. It is the host reference for the device kernel.

### gridcl-topology

- **`CellBlock::new`.** `CellBlock::new(cell, index_map, vertices, origin_ids, flags)`, so that Listing B10's `CellBlock::<D2>::new(Cell3::Tetrahedron, …)` exists (M1a question 3).
- **Origin ids on the device (question 8).** The words are (hi ^ 0x8000_0000, lo), so unsigned pair order equals i64 order.
  - The comptime fast path applies when every hi word equals 0x8000_0000, that is, when 0 ≤ id < 2^32.
  - Each mesh records `ids_fit_u32`.
- **`Topology<TD>`** holds:
  - the cell blocks;
  - the vertex `IndexMap` and the vertex origin ids;
  - the entity blocks and the connectivity per key, both `Option` until created;
  - the permutation info per block.

  It provides `create_entities`, `create_connectivity`, and the accessors that `DeviceGrid` forwards.
- **Dimensions (question 10).**
  - `create_entities(d)` accepts 0 ≤ d < tdim. Dimension 0 gives one `Point` block of the vertices.
  - Cells stay in `cell_blocks()`, whose vertices are in reference order, not in A.6 order. So `entity_blocks(tdim)` returns `EntitiesNotCreated(tdim)`.
  - `create_connectivity` supports `(tdim, d)`, which is `Downward` and comes from entity creation, and `(d, tdim)`, which is `Upward`, for 0 ≤ d < tdim.
  - `d → 0` is `EntityBlock::vertices`, and `tdim → 0` is `CellBlock::vertices`. Every other pair returns `UnsupportedConnectivity`.
- **Key emission (question 11).** Block b emits its keys at `e_b + i · n̂_b + c`, where `n̂_b` is the cell count rounded up to `VECTOR_PAD`.
  - The lanes are aligned vectors of consecutive cells.
  - Padding lanes write an all-ones sentinel key, which sorts last and forms one group. That group is dropped from the count and from the decode.
  - The 2^32 check includes the padding.

### gridcl-geometry

- **`PointSet<F, TD>`.**
  - `cell()`, `len()`, and `points()` and `weights()` on the host, in reference coordinates.
  - `tabulate(&CoordinateElement<TD>) -> Result<DeviceBuffer<F>>` gives values `[q][k]`, and `tabulate_derivatives` gives `[q][k][d]` (Listing B5).
  - Each tabulation is uploaded once per (element, point set) and cached; calls return `share()`s.
- **`FacetQuadRule<F, TD>`.**
  - `gauss(client, cells, degree)`, `for_grid(grid, degree)` and `get(cell) -> Result<&FacetPointSet<F, TD>>`.
  - A `FacetPointSet` is the `PointSet` of every facet point of the cell, in cell coordinates and facet-major order. It also provides `facet_offsets()` and the reference normal of each point.
  - A `facet_normals` field therefore has Σ_f n_f points per cell (question 22).
- **`QuadField`** gains `num_cells()`, `num_points()` and `chunks()`. `uninit` sizes its chunks from `device_properties(client).memory.max_page_size`.
- **`EVector<F>`** is stored in chunks, laid out `[k][g][cell]`, with `num_cells()` and `chunks()`.
  - The cell count is padded to `VECTOR_PAD` with copies of the last cell.
  - An empty block has no E-vector and launches nothing.
- **`DeviceGrid` additions (question 4):**
  - `fn evector(&self, b) -> Result<&EVector<Self::F>>`, built on first use and cached in a `OnceCell` of `Geometry`;
  - `fn origin(&self) -> <Self::GD as Dim>::Array<f64>`.
- **Block functions** are generic over `G: DeviceGrid`, as in Listing B5: `physical_points_block`, `jacobians_block`, `detj_block`, `pseudo_inverse_block`, `facet_normals_block`, `normals_block`, and `measure_block -> Result<f64>` (Listing B11).

### gridcl

- **`MeshBuilder<F, TD, GD>` (question 21).**
  - `new(client)`.
  - `nodes(coords: &[f64], origin_ids: Option<&[i64]>)`: coordinates `[node][gdim]` in f64. Without ids, each node's id is its index.
  - `cell_block(element, nodes: &[u32], origin_ids: Option<&[i64]>)`: cell→node lists in A.5 order. A cell's vertices are its first V nodes.
  - `build() -> Result<Mesh<F, TD, GD>>`.
  - **Checks:**
    - `check_precision`;
    - lengths and index ranges;
    - unique ids;
    - node roles;
    - at most one block per cell type.

    Empty blocks are allowed and launch nothing.
  - **Numbering** follows pipeline stage 8: vertices and nodes in order of the first cell that touches them, with blocks in call order.
  - **Coordinates.** The origin is the centre of the bounding box (0 for an empty mesh). Coordinates are stored relative to it, narrowed to `F`.
- **`EntityMap`** is an opaque placeholder until M9. `boundary()` is declared with Listing B4's signature and returns `Err(NotYetImplemented)` (question 5).
- **Tags.** The `tags: TagRegistry` field of Listing B3 is added in M4, its first user (question 16).

### Rules

- **Host copies (question 6).** ADR-0012 adds two items to CLAUDE.md and its listing in "Handing this design to Claude Code":
  - "the per-block read of `measure`'s reduction";
  - "uploads of input arrays at mesh creation, and of quadrature points and tabulations when a rule is created or a tabulation is first cached".
- **One partition per kernel.** Every M3 kernel takes its shape from one `LaunchPlan` (ADR-0009). Mixed-cell meshes get one launch per block, which keeps every kernel within six buffers.
- **Vector-generic kernels (question 13).** TopologyKeys, PermutationInfo, EVector and GeomFactors are generic over `N: Size`.
  - The lanes are consecutive cells of one block.
  - Connectivity is read lane by lane; its cell-fastest copy is M3s scope.
- **Factor-kernel vector sizes (question 23).** Factor kernels use `max_vector = tile`, so at tile width 1 they run at vector size 1. The invariance tests sweep 1 and every larger power of two up to 16 that the device offers ("Testing and validation").
- **Factor caching** by (rule id, factor flags) is deferred (question 9). M3's methods return fresh `BlockFields`.
- **Tests and the dev-dependency cycle.** Tests that use `HostMesh::build` live under `tests/`, never in `src/`. The dev-dependency cycle would otherwise give them a second copy of the crate under test.
