## Scope summary

The design calls gridcl a placeholder name. E1 gives the project its permanent name, tetraloma, and moves the
repository from github.com/tbetcke/gridcl to github.com/tetracl/tetraloma. Crates, Rust paths, environment
variables, scripts, CI, documentation and the Claude Code configuration are renamed mechanically. No public
type, function, kernel or test changes meaning. The name `tetraloma` is already reserved on crates.io
(0.0.0, published 2026-11-19, repository link github.com/tetracl/tetraloma).

## Preparation (before the branch; maintainer actions)

- **P1 ADR-0066 "The project is named tetraloma"** (docs/adr/0066-the-project-is-named-tetraloma.md, commit `adr: 0066 the project is named tetraloma`).
  It fixes the mapping in the table below, the policy for historical records (question 1), the environment
  variable switch (question 2) and the acceptance checks of this plan. The maintainer accepts it.
- **P2 Transfer and rename the repository** (one call, with the maintainer's go-ahead):
  `gh api -X POST repos/tbetcke/gridcl/transfer -f new_owner=tetracl -f new_name=tetraloma`.
  GitHub keeps the history, issues, PRs, labels and branch protection, and redirects the old web and git URLs.
  Then `git remote set-url origin git@github.com:tetracl/tetraloma.git` in both local clones, check
  that Actions are enabled for the repo in the tetracl org, and create the issue "E1 Rename to tetraloma"
  (label `enhancement`) with the task list.
- **P3 Branch** `e1-rename-tetraloma` from the up-to-date main, then commit this plan (`plan: E1`).
  Done out of order: the branch, ADR-0066 and this plan were committed before P2, and the **Issue**
  line is filled in after the transfer (Deviations log).

Done first, so that the issue, the PR and every URL written by the tasks point to the final location.
